1. Surface coverage: The hint text says only planes, cylinders, cones, spheres, tori and B-splines mesh. Pole and apex faces and tori wrapping round the tube are marked “not implemented yet”, and swept, offset and revolved surfaces are missing. Your hard-case samples exercise exactly these, so this is where real-world STEP files will fail first.
2. Make it build and test on Linux: STEPGzip looks tied to Apple’s Compression framework, since the plan marks the gzip test Darwin-only. Moving to zlib would let you run CI on Linux. It would also have caught compile errors in my STL code, which I couldn’t check here.
3. Use a watertightness check as a tessellator test: The edge map I built for STL can tell whether a mesh is closed and manifold. Running that over every sample would catch a bad seam or pole fix as a failing test.
4. Rename the shared types before 1.0: Bounds, BodyMesh, Options and ParseError now serve STL as well, but they live under STEP. FaceMesh.surface is non-optional, so a mesh format with no analytic faces can’t fill faces. A neutral namespace and an optional surface would be breaking changes, so they’re cheaper now than later.
5. Trim the API surface: There are five layers (EdgeModel, Geometry, Topology, Bodies, Assembly), each with read and load variants. Assembly could be the main result, with the others as views of it. I had to add loadAssembly for STL for this reason.
6. Stop reusing STEP-specific error cases: ParseError.Kind has notSTEP, unresolvedUnits and assembly, which don’t fit STL. I used .malformed for non-STL input, which is vague.
